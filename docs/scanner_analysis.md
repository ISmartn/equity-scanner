# Scanner analysis dataset

Research export for tuning momentum scanner thresholds.

## Signal outcomes (DB feedback loop)

Persist 1/3/5/10/20d forward returns + MFE/MAE into SQLite `signal_outcomes`, and write a baseline-vs-refined comparison report:

```bash
npm run scanner:outcomes
```

Outputs:

- Table `signal_outcomes` (keyed by `pattern_signals.id`)
- `data/scanner_analysis/outcome_comparison_summary.json`
- API: `GET /api/scanner/outcomes/summary`

Scoring weights live in `backend/app/services/scanner/scoring.py` (optional overrides: `data/scanner_score_weights.json`).

## Failure-pattern / quality-gate analysis

Winner vs loser Day-T feature study + before/after validation for `quality.py` gates:

```bash
npm run scanner:failures
```

Outputs:

- `data/scanner_analysis/failure_pattern_analysis.json`
- `data/scanner_analysis/quality_gates_before_after.json` (regenerated by the validation helper in the same workflow)

Hard gates (engine): weak trigger close `< 0.65`, climactic volume without strong close, VCP base depth `> 25%`, prior 20d run-up `> 18%` (higher-low exception up to 25%). Cap is configurable via `data/scanner_score_weights.json` → `quality.max_20d_runup_pct`.

July study: `npm run scanner:july20d` → `data/scanner_analysis/july_20d_exhaustion_report.md`.

## Generate

```bash
npm run scanner:analysis -- --skip-scan --min-score 70
```

| Flag | Default | Meaning |
|------|---------|---------|
| `--min-score` | 70 | Minimum signal score |
| `--days` | 22 | Number of scan dates to include |
| `--pre-scan-weeks` | 5 | Weeks of OHLCV before each signal |
| `--skip-scan` | off | Reuse existing `pattern_signals` in DB (fast) |

Use `--days 48` (or higher) to include all stored scan history.

## For LLM / chat analysis (~1 MB)

**`data/scanner_analysis/scanner_refinement_llm.json`**

Compact export designed for LLM context limits (~1 MB for 5,700+ signals). No full OHLCV paths — tabular `signal_rows` + aggregates + 15 top/bottom examples with mini chart snippets.

```bash
# From existing full dataset (fast, no DB)
npm run scanner:analysis:llm

# Or produced automatically when you run scanner:analysis
npm run scanner:analysis -- --skip-scan --min-score 70 --days 48
```

Structure:

```json
{
  "schema_version": "1.1",
  "purpose": "LLM-friendly scanner refinement dataset",
  "how_to_read": { "signal_rows": "array-of-arrays; see signal_columns", ... },
  "summary": { "win_rate_5d_pct", "median_return_5d_pct", ... },
  "aggregates": { "by_pattern_5d", "by_macro_pass_5d", ... },
  "examples": { "top_5d_winners": [...], "bottom_5d_losers": [...] },
  "signal_columns": ["trade_date", "ticker", "pattern_type", "score", ...],
  "signal_rows": [[ "2026-01-05", "BAJAJCON", "pocket_pivot", 100.0, ... ], ...]
}
```

Use this file when asking an LLM to suggest threshold changes, pattern ranking, or score-band tuning.

## Full file (charts / deep research, ~115 MB)

**`data/scanner_analysis/scanner_refinement_dataset.json`**

Single JSON with schema version, aggregates, and full per-signal records:

```json
{
  "schema_version": "1.0",
  "filters": { "min_score": 70, "pre_scan_sessions": 25, ... },
  "summary": { "win_rate_5d_pct", "by_pattern_5d", ... },
  "aggregates": { "by_pattern_5d", "by_macro_pass_5d", "by_triggered_5d", "by_score_band_5d" },
  "signals": [
    {
      "signal_id": "RELIANCE|2026-07-06|pocket_pivot",
      "trade_date", "ticker", "pattern_type", "score", "pattern_score",
      "macro_pass", "triggered_today", "setup_ready",
      "entry_close", "return_5d_pct", "return_10d_pct", "return_20d_pct",
      "max_favorable_pct", "max_adverse_pct",
      "details": { /* pattern detector output */ },
      "pre_scan_path": [ /* 25 bars, day_offset -25..-1 */ ],
      "daily_path": [ /* forward bars from signal day */ ]
    }
  ]
}
```

## Companion files (same run)

| File | Format | Use |
|------|--------|-----|
| `scanner_refinement_llm.json` | JSON | **LLM** — compact tabular + aggregates (~1 MB) |
| `scanner_refinement_dataset.json` | JSON | **Full** — nested data + OHLCV paths (~115 MB) |
| `signals_1m.csv` | CSV | Spreadsheet: one row per signal (no paths) |
| `signals_1m_pre_scan.csv` | CSV | Flat pre-scan OHLCV (join on `signal_date` + `ticker`) |
| `signals_1m_daily.csv` | CSV | Flat forward OHLCV after signal |
| `manifest.json` | JSON | Summary only (no signal rows) |

## Analysis ideas

- Slice `aggregates.by_pattern_5d` to raise `MIN_SCORES` for weak patterns
- Filter `signals` where `macro_pass=true` vs false
- Compare `triggered_today` vs `setup_ready` forward returns
- Plot `pre_scan_path` + `daily_path` for manual chart review
- Correlate `details.pattern_score` vs `return_5d_pct`

## Regenerating

```bash
npm run scanner:analysis -- --skip-scan --min-score 70 --days 48
npm run scanner:analysis -- --min-score 70          # re-scan + rebuild (~10 min)
```
